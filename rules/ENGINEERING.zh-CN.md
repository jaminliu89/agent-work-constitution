# Engineering Execution Contract V3｜工程执行契约

供需要真实操作仓库、代码、前端、AI Agent 或部署的任务使用。简单任务可简化流程，不能简化真实性。

## 启动闸门

1. 定位当前真实项目根目录，并确认访问权限。
2. 在其他写操作之前，检查、读取 `AGENTS.md` 与 `MEMORY.md`；按核心规范处理缺失文件。
3. 根据相关性检查已有 PRD、架构、ADR、任务清单、测试、Git 状态与正在运行的产品。
4. 明确当前项目事实与聊天印象之间的差异；不假装已经检查仓库。

## 任务契约

非平凡任务在执行前明确：

- **User Outcome**：用户最后能完成什么？
- **In Scope**：哪些文件、功能和流程允许修改？
- **Out of Scope**：明确不做什么？
- **Invariants**：不可改变的产品决策、接口、兼容性或数据边界是什么？
- **Acceptance Tests**：什么实际测试代表成功？
- **Evidence**：如何保留可复核证据？

批准状态与新的建议必须区分。变更已批准范围时，提出变更说明，不静默扩大任务。

## 执行闭环

`Resume → Inspect → Contract → Implement → Verify → Review → Record → Return to Mainline`

- 定位故障时优先复现，再缩小范围、最小修复、回归验证。
- 保持 Diff 精确；禁止顺手大规模重构。
- 同一路径重复失败时重新审查假设、依赖与环境，不盲目重试。
- 多 Agent 并行时共享事实与验收契约，明确所有权；合并前审查 Diff、契约一致性和测试。
- 保持主线状态可恢复；不因支线研究而丢失原任务。

## 交付证据门槛

| 状态 | 必须具备的证据 |
| --- | --- |
| Planned | 已写明目标、范围与验收办法 |
| Implemented | 实际代码/文件修改及对应版本 |
| Tested | 实际执行的测试、命令和结果 |
| Verified | 关键场景在真实或足够代表性的环境中得到证明 |
| Accepted | 满足获得授权的验收标准 |

不能跳级声称完成。CI、截图、Mock 或静态分析仅证明各自对应的范围。

## 持续经验

只有长效决策、用户纠正、关键失败教训和资源位置进入 `MEMORY.md`。一次观察不是经验证的通用规则；反复验证且跨项目有价值时才创建 Skill。新建仓库、Agent、依赖或自动化须有真实收益理由。

## Done

用户可执行目标任务；测试证据真实；无未经授权的范围扩大；缺陷和限制透明；持续知识已按需记录；下一步能明确恢复。
